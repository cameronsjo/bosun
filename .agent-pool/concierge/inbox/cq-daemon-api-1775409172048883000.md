## GH#220 — HTTP force-trigger endpoint: DONE

**Change:** `internal/daemon/server.go` — `handleManualTrigger`

### What changed

Two code paths now both read the body and decode an optional `TriggerRequest` JSON payload:

1. **With `WebhookSecret`**: body bytes already read for HMAC → `json.Unmarshal(body, &req)` on those same bytes (zero-copy of re-read)
2. **Without secret**: reads body up to `maxWebhookBodySize`, then `json.Unmarshal` if non-empty

In both paths, `req.Force` (default `false` if body absent or field omitted) is passed to `TriggerReconcile` instead of the hardcoded `false`.

### Key design choices

- Empty body → `req` stays zero-value → `Force: false` → backward compatible
- Invalid JSON body → `400 Bad Request` (not silent ignore, consistent with socket server behavior)
- No new struct — reuses `TriggerRequest{Source, Force}` already defined in `socket.go`

### Verification

`make test` — all tests pass.

### Usage after this change

```bash
# Force reconcile via HTTP manual trigger
curl -X POST http://localhost:8080/webhook/manual \
  -H "Content-Type: application/json" \
  -d '{"force": true}'

# With HMAC signature
BODY='{"force": true}'
SIG=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')
curl -X POST http://localhost:8080/webhook/manual \
  -H "X-Signature: sha256=$SIG" \
  -H "Content-Type: application/json" \
  -d "$BODY"
```
